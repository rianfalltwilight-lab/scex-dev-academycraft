# AcademyCraft + ExtraAcademy 0.0.32 自动化与交互

基线：`v0.0.31-scex-data-sync` / `4993aede05974ffe8f75994b2bcde7cdda92c6a2`。
版本：`0.0.32-scex-automation-ui`，Minecraft 1.21.1 / NeoForge 21.1 / Java 21。

## 机器和容器

相位发电机上面接收流体容器、侧面接收充电物品，下面输出返回容器和充满的物品。太阳能与风力底座从上面或侧面接收充电物品，下面只取出充满的物品；风力底座上半部代理同一份底座库存。成型机、熔合炉继续使用原有分面规则。节点、矩阵和干扰器受所有者限制的槽位不新增无身份自动化入口。

想象熔合炉和相位发电机继续支持旧虚相位液体单元，并通过 NeoForge 标准流体能力接收容器。预演排空后检查返回容器的完整物品组件与出口容量，再执行转移。出口被占用或容器无法排出可接受数量时不消耗输入；支持部分排空的容器以实际剩余内容返回。只接收虚相位液体。菜单与自动化共用流体输入判定；容量、生成和加工数值、`4 FE = 1 IF` 均沿用原规则。

新增物品能力直接访问现有机器库存，不建立第二份物品存储。模拟调用不修改库存；失效或已拆卸机器的旧物品接口拒绝后续转移，风力上半部代理也核对原底座身份。

## 配方和数据包

成型机与熔合炉使用原生 `RecipeManager.CachedCheck`。它保存上次成功的配方 ID，每次仍从当前管理器解析并验证输入。成型模式、输入数量和重载后的配方必须重新满足条件。已加载熔合炉的活动配方发生变化时清除旧进度；成型机保留原有重载身份检查。

新增两个被现有配方实际使用的物品标签：

| 标签 | 默认内容 | 使用者 |
|---|---|---|
| `academy:machine_inputs/iron_ingots` | `minecraft:iron_ingot` | 强化铁板成型、约束锭熔合 |
| `academy:machine_inputs/silicon_feedstock` | `minecraft:sand` | 虚数硅熔合 |

数据包使用 `data/academy/tags/item/machine_inputs/iron_ingots.json` 或 `silicon_feedstock.json` 追加材料；`replace: true` 可替换默认分类。原配方的产物和数量保持不变。配方本身继续支持原生数据包替换与 NeoForge 条件。

缓存只减少命中后重复扫描候选的工作，不减少业务查询次数；未命中仍需搜索。重叠的自定义配方遵循原生“上次成功 ID 优先”行为。熔合炉保留原有磁盘进度格式，首次加载时绑定当前匹配配方；运行时配方身份不写入存档。

## 原生交互

- 设置页的开关、编辑 HUD 和返回接入原生按钮；Tab 聚焦屏外设置时自动滚动到该项。
- 技能页的预设、技能槽和下拉选项接入原生按钮；Enter/Space 选择，清空为下拉首项，Escape 先关闭下拉。下拉打开时底层控件不参与焦点切换。
- 成型机模式箭头支持鼠标和键盘，旁白包含当前模式。
- 信息卡的能量、缓冲、液体、容量、信息和模式标签支持中英日翻译；长标签适配标签列宽，避免覆盖数值。

保留现有背景、图标、布局和翻译。原生按钮提供焦点和旁白语义，焦点框在原美术层绘制。本批没有重写全部终端页面或 HUD 拖拽编辑器。

## 验证与交付

最终实际执行数、结果、截图和源码／JAR 身份以 `evidence/automation-ui-0.0.32/final-validation.json` 为准。新增服务端场景验证漏斗自然 tick、模拟守恒、容器返回、失效接口、原生缓存及真实数据包重载。客户端程序通过生产输入入口驱动设置、预设、技能槽和机器模式，核对真实服务器回包、旁白文本、中英日语言和有效 GUI 缩放，并保存截图供审阅；不将程序输入或旁白文本检查称为人工操作或听觉体验测试。

缓存场景的两次真实机器查询分别检查 2 个、1 个候选；该记录只说明测试配方下的缓存复用，不推断整服 MSPT 收益。真实 `reloadResources` 覆盖标签追加、标签替换、同名配方更新和条件删除，结束后恢复原数据包。

最终验证为 342 项 JUnit／契约检查、473 项真实 GameTest（`MONARCH/gt-r3`）和 85 项客户端检查（`MONARCH/client-r2`）通过。18 张截图按中英日、GUI 缩放 2/3、设置／技能槽／成型机逐张审阅通过；客户端完成原生保存后正常退出，服务端亦正常退出。使用的测试输入为 `build/automation-ui-0.0.32-r3-tested`，发行封装只更新构建证据元数据，运行类和资源逐条校验一致。

初轮截图审阅发现日语信息卡长标签覆盖数值，修复后重新构建并验证。中间 `gt-r2` 有一次旧影子追逐场景在固定 60 tick 内位移不足：实体正常 tick，玻璃完整、伤害为零、维持 CP 扣除正确；同一份 JAR 在全新 `gt-r3` 完整复测通过。原失败日志、退出码和分析保留，未放宽断言；现有记录不足以定位具体 AI 寻路波动原因，本版不宣称修复该导航问题。

本轮优先尝试 Vicerach，但启动前可用内存低于既定 6 GiB 门槛，未启动测试 Java；随后回退 Monarch 的 D 盘分类目录，按 2.5 GiB 新增预算检查通过，并从内网复用同一冻结底座。服务端与客户端串行运行，取得同一窗口锁，限制 1536 MiB 堆和 2 个 CPU 工作线程。客户端收尾等待原生区块保存状态就绪后保存，验收要求全部维度保存及进程正常退出。测试探针独立打包，不进入发行主 JAR。

构建锁定 NeoForge 21.1.248，运行范围保持 `[21.1,21.2)`；协议保持 `academy-1.21.1-payload-v20-data-v4`，存档保持 v4。注册 ID、技能数值与 Extra 能力范围不变。升级时客户端与服务端安装同一发行版本；从 0.0.30 或更早版本升级仍需保留组件迁移前的存档备份。

私密 GitHub Release 交付主 JAR、对应源码 ZIP 和 `SHA256SUMS.txt`。本轮不部署生产服或玩家更新源。
