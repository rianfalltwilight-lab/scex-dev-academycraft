# AcademyCraft 0.0.22-scex-wireless 开发说明

目标环境：Minecraft 1.21.1、NeoForge 21.1.248、Java 21.0.12、Gradle Wrapper 9.2.0、ModDevGradle 2.0.141。由已发布 0.0.21-scex-charging 冻结源码派生，保留 LICENSE、NOTICE 和原有上游提交记录。本任务不部署生产服务器。

## 实际修改

- `energy/impl/WirelessNet.java`：节点增加能量时共享缓冲必须减少，节点减少时缓冲增加；按缓冲余量限制传输。把可用缓冲计入均衡目标，避免所有节点为空时缓冲残留无法输出。仍沿用一个矩阵连接多个节点的网络结构、容量、带宽和范围，不增加区块扫描。
- `client/block/entity/render/MatrixRender.java`：使用 Minecraft BlockModelRotation 对 JSON y 角度采用的负向旋转，使东西方向束能板绕正确的底座中心转动；原模型、材质、漂浮和三板公转保留。
- `client/gui/AcademyBaseUI.java`：节点与矩阵两种无线列表共用密码输入绘制。空输入有稳定光标、选中行高亮、输入掩码，以及完整目标名称和坐标提示；Enter 连接、Esc 取消。长名称和密码掩码不再相互覆盖。
- `world/menu/AcademyMenu.java`：共享背包槽位 x 从 6 改为 8。直接测量随包 ui_inventory.png 的第一个槽框中心，结果为 16 逻辑像素，而旧物品中心为 14。
- `world/menu/{BaseNode,PhaseGen,SolarGen,WindGenBase,WindGenMain,ImagFusor,MetalFomer,AbilityInterferer,Matrix}Menu.java`：机器槽位统一向右校正 2 逻辑像素，太阳能电池槽 y 从 81 调为 80，与实际共用的 windbase 背景一致。修改真实 Slot 坐标，因此物品、悬停高亮和点击区域使用同一坐标；槽位索引、物品限制和存档结构不变。

## 复现与验证边界

1. 修复前矩阵传输用例通过私有网络初始化、错误密码拒绝、正确密码接入两个节点，但输入 1000 IF 后网络总量变成 1160 IF；修复后传到输出桥 3999 FE，总量精确保持 1000 IF，剩余小数保存在网络内。另检查空节点读取缓冲、满缓冲边界，200 次真实网络 tick 守恒。
2. 修复前真实客户端四方向各两张截图，东西方向旋转原点误差为约 1.414 格；修复后四方向误差均为 0。该视觉夹具在隔离世界安装真实方块、核心和三块约束板，不等同于生存放置流程的完整证明。
3. 修复前纹理测量测试失败：背包首槽框中心 16、物品中心 14；修复后全 36 个共享背包槽框检查通过。机器槽位另由原纹理测量和两种 GUI 缩放的实际客户端截图复核。
4. 343 项 JUnit 检查通过，其中包含静态源码与资源契约，不能当作 343 项游戏功能。285 项 GameTest 通过，包括本轮矩阵多节点私有网络传能用例。常规 GameTest 命名空间未重跑额外 `academy_charging` 的专用 5 项长蓄力用例。
5. 打包客户端在 960×540 / GUI 2 与 1280×720 / GUI 3 各完成现有全机器流程，均 PASS、各 94 条证据。覆盖节点三阶、矩阵、相位/太阳能/风力、虚能融合机、金属处理机、干扰机、输入/输出能源桥、开发机及无线页；同时复核 Jade、JEI 隔离组合。两条流程均包含技能按键和蓄力释放。
6. 用户报告的“改名 123 提示保存成功却仍是默认名”尚未复现：0.0.21 与本轮候选的真实双客户端均可保存、显示、同步名称。候选加入两个相邻节点，其中一个也叫 123、一个保留默认名，仍通过 13 阶段认证与连接验证。此项不能写成已定位或新增修复。
7. 长期维护只读核对了服务端、客户端发行源、玩家更新源、远程下载，均为已发布 0.0.21 同一 SHA-256。该证据不能证明报告者本机已同步，也不能排除其本地资源包/额外模组影响。

能源桥的列表发现无线节点；节点的无线页发现已初始化矩阵。矩阵通过连接多个节点组成网络，本轮没有增加能源桥直接连接矩阵的接口。因此不能将传能守恒修复描述为“矩阵现在出现在能源桥直连列表”。

## 旧功能、性能与部署

- 已发布的蓄力伤害 2.5 倍及其他旧修复沿用 0.0.21。最终交付审计会逐条比较 JAR 条目，确认旧蓄力代码和资源未改变；本次 JUnit、常规 GameTest、真实客户端全机器/技能流程是回归证据，不能替代专用长蓄力全套复测。
- 本轮 579 个 PNG、440 个 JSON 校验通过，所有 `assets/` 与 `data/` 条目与 0.0.21 完全一致，没有重画原始模型或材质。
- 修改网络 tick 的操作是常数次数值运算，保留现有遍历规模；本次未进行整合包压力测试、完整 MSPT/JFR/GC 配对测量。部分功能取证期间宿主有其他开发任务并发，不据此给出性能改善结论。
- 默认关闭的测试代码调整：节点改名夹具使用 123、加入同名邻居、暂停并截取空/已输入密码；新增矩阵四方向视觉探针及矩阵传能 GameTest。正常运行没有启用这些系统属性。
- 客户端与服务端一起使用 0.0.22，替换旧 AcademyCraft 单一 JAR，不与 0.0.21 共存。协议 v15/data-v4 不变，无存档迁移。生产备份、停服、部署、玩家更新由 SCEX-长期维护接管。
- 回滚时恢复备份的 0.0.21 JAR；如要回到部署前的能量/网络状态，同时使用同一时点世界备份，不单独回滚部分网络数据文件。
